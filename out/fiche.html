Cycle de vie des commandes

terraform init
backend + modules + providers. Sans danger à relancer
init -upgrade
monte modules et plugins au plus récent autorisé
init -reconfigure
ignore le backend existant, sans migration
init -migrate-state
copie le state vers le nouveau backend
init -backend=false
saute le backend
terraform fmt
formate (-recursive, -check, -diff)
terraform validate
syntaxe + cohérence interne
terraform plan
compare et propose, ne change rien
terraform apply
exécute (confirmation, ou fichier de plan)
terraform destroy
détruit tout le workspace courant

Options de plan et d'apply

-out=FICHIER
sauve le plan
apply FICHIER
applique ce plan, sans confirmation
-var 'k=v'
une variable
-var-file=F
un fichier .tfvars
-destroy
plan de destruction totale
-refresh-only
aligne le state sur le réel
-refresh=false
sans synchroniser le state
-replace=ADR
force le remplacement d'une instance
-target=ADR
exceptionnel seulement
-detailed-exitcode
0 rien · 1 erreur · 2 changements
-auto-approve
saute la confirmation (apply)
-parallelism=n
10 par défaut
-lock=false
dangereux
-lock-timeout=3s
attend le verrou
