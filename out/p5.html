Boucles et cycle de vie

Créer dix ressources sans écrire dix blocs, et contrôler finement ce que Terraform a le droit de faire. Le sujet le plus piégeux du début : count contre for_each.

Objectifs
  • Choisir entre count et for_each, et expliquer pourquoi.
  • Écrire un bloc dynamic et savoir quand l'éviter.
  • Utiliser lifecycle : prevent_destroy, create_before_destroy, ignore_changes, replace_triggered_by, conditions.

5.1 count : N instances numérotées

resource "local_file" "copie" {
  count    = 3                                  # un entier
  filename = "${path.module}/copie-${count.index}.txt"   # count.index : 0, 1, 2
  content  = "copie numero ${count.index}\n"
}
# adresses : local_file.copie[0]  local_file.copie[1]  local_file.copie[2]

count sert aussi de interrupteur : count = var.creer_bonus ? 1 : 0 crée la ressource ou non. Limites : la valeur doit être connue avant toute opération distante (pas d'attribut calculé à l'apply), et on ne combine pas count et for_each dans un même bloc.

5.2 for_each : une instance par clé

resource "local_file" "avec_for_each" {
  for_each = toset(var.noms)                 # une MAP ou un SET de strings
  filename = "${path.module}/fe-${each.key}.txt"
  content  = "salut ${each.key}\n"
}
# adresses : local_file.avec_for_each["alice"]  ["bob"]  ["chloe"]

each.key est la clé de la map (ou l'élément du set) ; each.value est la valeur (identique à la clé pour un set). Une liste ne passe pas telle quelle : toset() (les listes ne sont pas converties implicitement).

Limites : clés connues avant l'apply, pas de valeurs sensibles, pas de fonctions impures comme uuid ou timestamp.

On retire bob de la liste ["alice", "bob", "chloe"]. Résultat observé avec Terraform 1.17.0 :

Le conseil de la doc

count pour des instances presque identiques ; for_each « quand certains arguments doivent avoir des valeurs distinctes qui ne se déduisent pas d'un indice entier ».

5.3 dynamic : répéter un bloc imbriqué

resource "aws_elastic_beanstalk_environment" "tfenvtest" {
  # ...
  dynamic "setting" {
    for_each = var.settings
    content {
      namespace = setting.value["namespace"]
      name      = setting.value["name"]
      value     = setting.value["value"]
    }
  }
}

Un bloc dynamic "setting" génère un bloc imbriqué setting { … } par élément. L'itérateur s'appelle comme le label (setting) et expose .key et .value (variable iterator pour le renommer).

La doc te prévient

« Abuser des blocs dynamic rend la configuration difficile à lire et à maintenir. » Utilise-les surtout pour offrir une interface propre dans un module réutilisable, et écris les blocs en toutes lettres quand c'est possible.

5.4 lifecycle : encadrer Terraform

ArgumentEffet
prevent_destroyRejette tout plan qui détruirait l'objet, y compris terraform destroy. À utiliser avec parcimonie ; n'agit pas si tu retires le bloc de la config.
create_before_destroyCrée le remplaçant avant de détruire l'ancien. Optionnel : certains types de ressources ont des conflits de nom.
ignore_changesignore_changes = [tags] : ces attributs sont exclus de la planification d'update (un outil externe peut les gérer).
replace_triggered_byForce le remplacement quand une ressource ou un attribut référencé change.
precondition / postconditionVérifie une hypothèse avant création / une garantie après création ou lecture. Chacune : condition + error_message.
TD 5

count, for_each et protection

≈ 25 min · aucun compte cloud
  1. Crée les deux boucles côte à côte. Dans un dossier td5 : 
    terraform {
  required_providers {
    local = {
      source  = "hashicorp/local"
      version = "~> 2.5"
    }
  }
}

variable "noms" {
  type    = list(string)
  default = ["alice", "bob", "chloe"]
}

variable "creer_bonus" {
  type    = bool
  default = false
}

resource "local_file" "avec_count" {
  count    = length(var.noms)
  filename = "${path.module}/count-${var.noms[count.index]}.txt"
  content  = "salut ${var.noms[count.index]}\n"
}

resource "local_file" "avec_for_each" {
  for_each = toset(var.noms)
  filename = "${path.module}/fe-${each.key}.txt"
  content  = "salut ${each.key}\n"
}

resource "local_file" "precieux" {
  filename = "${path.module}/precieux.txt"
  content  = "a ne pas detruire\n"

  lifecycle {
    prevent_destroy = true
  }
}

resource "local_file" "bonus" {
  count    = var.creer_bonus ? 1 : 0
  filename = "${path.module}/bonus.txt"
  content  = "bonus\n"
}

    $ terraform init
$ terraform apply -auto-approve
$ terraform state list

    Attendu : « Apply complete! Resources: 7 added ». Regarde les adresses : avec_count[0] contre avec_for_each["alice"].

  2. Retire bob et compare. Ne l'applique pas, lis seulement le plan. 
    $ terraform plan -var='noms=["alice","chloe"]'

      # local_file.avec_count[1] must be replaced
      ~ filename = "./count-bob.txt" -> "./count-chloe.txt" # forces replacement
  # local_file.avec_count[2] will be destroyed
  # (because index [2] is out of range for count)
  # local_file.avec_for_each["bob"] will be destroyed
  # (because key ["bob"] is not in for_each map)
Plan: 1 to add, 0 to change, 3 to destroy.

    Question : combien de ressources liées à chloe sont touchées côté count ? (Deux : [1] reçoit son nom, [2] disparaît.) Et côté for_each ? (Aucune.)

  3. Utilise count comme interrupteur. 
    $ terraform plan -var creer_bonus=true

    Attendu : local_file.bonus[0] will be created et « Plan: 1 to add ». Avec creer_bonus=false (défaut), rien n'est créé.

  4. Teste la protection. 
    $ terraform destroy -auto-approve
$ terraform state list | wc -l

    Error: Instance cannot be destroyed
Resource local_file.precieux has lifecycle.prevent_destroy set, but the plan
...

    Le plan est rejeté avant toute destruction : le state list | wc -l affiche toujours 7.

  5. Lève la protection et nettoie. Passe prevent_destroy à false dans main.tf, puis : 
    $ terraform destroy -auto-approve

    Attendu : « Destroy complete! Resources: 7 destroyed. » Pas besoin d'apply avant : lifecycle est lu dans la configuration, pas dans le state. La protection est une décision de configuration, pas un verrou magique.

Pour aller plus loin

Transforme noms en map ({ alice = 8080, bob = 3000 }) et utilise for_each = var.ports avec each.value dans le contenu du fichier : tu as maintenant des valeurs distinctes par instance, le cas d'usage idéal de for_each.
