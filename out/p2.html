Parler HCL

HCL est le langage des fichiers .tf. Peu de règles de syntaxe, mais un vocabulaire d'expressions à connaître : types, références, conditions, boucles for, fonctions.

Objectifs
  • Distinguer arguments et blocs, et respecter les règles d'identifiants et de commentaires.
  • Manipuler les types (string, list, map…) et les convertir.
  • Utiliser références, conditions, expressions for et fonctions, et les tester dans terraform console.

2.1 Arguments et blocs

# Un ARGUMENT : un nom, un "=", une valeur
image_id = "abc123"

# Un BLOC : un type, des labels, un corps entre accolades
resource "aws_instance" "example" {
  ami = "abc123"          # argument dans le bloc

  network_interface {     # bloc imbriqué
    # ...
  }
}
Règles de la doc
  • Identifiants : lettres, chiffres, _ et - ; le premier caractère ne peut pas être un chiffre.
  • Commentaires : # est le style par défaut. // et /* … */ existent mais ne sont pas idiomatiques.
  • Encodage : UTF-8 obligatoire ; fins de ligne LF ou CRLF acceptées (LF est idiomatique).
  • Fichiers : tous les .tf d'un répertoire forment un seul document. Les séparer n'a aucun effet sur le comportement, seulement sur la lisibilité. Un sous-dossier est un autre module.

Conversions automatiques : un nombre ou un booléen devient une chaîne si besoin (15 ↔ "15"), et une chaîne valide devient un nombre ou un booléen. Pas de conversion automatique avec l'opérateur d'égalité. Pour un set, convertis d'abord : tolist(var.mon_set).

2.4 Conditions et boucles for

# Condition : condition ? valeur_si_vrai : valeur_si_faux
var.a == "" ? "default-a" : var.a

# Les deux résultats doivent avoir le même type : convertis explicitement si besoin
var.example ? tostring(12) : "hello"

# Expression for -> liste
[for s in var.list : upper(s)]

# Expression for -> map, avec filtre
{for s in var.list : s => upper(s) if s != ""}

# Avec deux symboles : index+valeur (liste) ou clé+valeur (map)
[for i, v in var.list : "${i} is ${v}"]
À savoir

Entre crochets [ ] tu obtiens une liste (tuple) ; entre accolades { } un objet, et il faut alors fournir clé et valeur séparées par =>. Le suffixe ... après la valeur regroupe les doublons de clé dans des listes.

Astuce

terraform console est ton bac à sable : tu y testes fonctions et expressions sans rien déployer, même quand le state est vide. Sortie par exit, Ctrl-C ou Ctrl-D. En script : echo 'split(",", "foo,bar,baz")' | terraform console.

TD 2

Le bac à sable : terraform console

≈ 20 min · aucun fichier à créer

Place-toi dans le dossier du TD 1 (ou dans n'importe quel dossier), puis ouvre la console. Tape chaque expression et compare avec le résultat attendu.

  1. Ouvre la console et teste des chaînes. 
    $ terraform console
> upper("terraform")
> join("-", ["a", "b", "c"])
> "Bonjour ${upper("alex")}"

    Attendu : "TERRAFORM", "a-b-c", "Bonjour ALEX".

  2. Types et conversions. 
    > tostring(15)
> tolist(toset(["b", "a", "b"]))
> length({ a = 1, b = 2 })

    Attendu : "15", tolist(["a", "b"]) (un set n'a pas de doublon) et 2. Question : pourquoi le résultat est-il trié et sans doublon ?

  3. Une condition. 
    > 5 > 3 ? "grand" : "petit"
> "" == "" ? "vide" : "plein"

    Attendu : "grand" et "vide".

  4. Des expressions for. 
    > [for s in ["a", "b", "c"] : upper(s)]
> { for s in ["a", "b"] : s => upper(s) }
> [for i, v in ["x", "y"] : "${i}-${v}"]
> [for n in [1, 2, 3, 4] : n * 10 if n > 2]

    Attendu : ["A", "B", "C"], un objet { "a" = "A", "b" = "B" }, ["0-x", "1-y"] et [30, 40] (la console les affiche sur plusieurs lignes).

  5. Calculer un réseau et sortir. 
    > cidrsubnet("10.0.0.0/16", 8, 2)
> cidrnetmask("172.16.0.0/12")
> exit

    Attendu : "10.0.2.0/24" et "255.240.0.0" (la doc donne ce second exemple). Défi : trouve la fonction qui renvoie le plus grand de 3 nombres.

Corrigé du défi

max(5, 12, 9) renvoie 12 : c'est l'exemple de la documentation.
